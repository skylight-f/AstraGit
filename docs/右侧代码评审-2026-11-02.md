# 右侧代码评审

搜索框右侧新增评审按钮，切换可调宽度的右侧模块。原 Git 工作台、项目提交和左侧操作栏继续共存。关闭面板保留当前报告；切换项目清除报告并取消旧项目请求。

评审范围默认为当前项目全部仓库，可选择单个仓库；支持完整工作区最终内容（相对 HEAD，包括未跟踪文件）与仅暂存内容。服务端自行解析项目仓库、状态和差异，不接受客户端上传的任意代码或系统指令。干净范围不调用模型，存在未解决冲突时提示先处理冲突。

复用现有 AI 模型配置及 OpenAI completions / Responses / Anthropic 请求实现。Codex 复用独立、只读、禁止工具的临时会话；不使用实际项目目录执行 AI 工具。请求发出后支持显式取消。结果为结构化 JSON，展示改动概述、修改影响、风险问题、修复建议及建议验证项。问题文件可以定位到 Git 工作台差异。模型输出以纯文本呈现，仓库与文件引用必须在本次范围内。

每次报告保存范围指纹，覆盖文件内容、文件集合、仓库集合、分支和 HEAD。评审期间内容变化则拒绝结果；展示后按面板激活、窗口聚焦及周期检查过期状态，过期报告不能直接定位。新增文件、切换分支等也会使旧报告失效。

最多 20 个仓库 / 2000 个文件，逐行差异总预算 40000 字符。大文件、生成文件、二进制及子模块引用等未完整评审的内容列出范围说明。仅基于提供差异分析，不自动修改代码、不运行测试，也不宣称完成整个项目的依赖分析。

验证：集成测试覆盖多仓库、单仓库、暂存/工作区隔离、无改动、评审期间新增与修改、格式及范围校验、供应商失败脱敏、3 秒内取消通知以及真实 index/HEAD 不变。开发版通过本机模拟模型验收；不将模拟结果作为真实模型评审质量结论。本轮不推送或发布。

补查修复：评审仓库选项独立复用工作台元数据，默认范围因冲突或文件过多受阻时仍可选择其他仓库。问题定位先刷新目标仓库再判断文件是否存在，修复新文件因旧快照误报失效的问题；未跟踪文件定位到未暂存差异。

2026-11-03 流式评审：模型接口使用 SSE，桌面客户端接收 NDJSON 事件。展示供应商公开返回的思考内容或思考摘要；每个完整问题对象通过仓库、文件与字段校验后立即显示，无需等待整份 JSON 完成。取消、中断或格式失败时保留已接收的思考与问题，并明确标记为未完成；最终成功仍需完整报告校验及范围指纹复核。

取消评审固定的 6000 token 输出额度、40000 字符报告上限及 12 条问题/影响/建议数量限制。OpenAI 兼容接口不发送输出额度字段；Anthropic 协议必填的 max_tokens 使用模型已配置容量，供应商自身上限继续适用。输入差异预算保持原有范围策略。流式生成按持续活动续期，不再被客户端固定 120 秒总时限中断；支持显式取消，连接断开时同时终止模型请求与响应流。Codex 使用独立只读临时会话，只展示其公开思考摘要。

最终验证：全仓 lint、桌面 TypeScript、前端生产构建、锁文件及隔离检查通过。默认并发全量 586 通过、1 个既有历史比较超时；该项单独通过。并发上限 4 的全量复测 577 通过、0 失败，环境缺少 Git LFS 路径跳过 10 项；指定项目已有 Git LFS 3.8 后相关 12 项全部通过、0 跳过。新增文件差异定位、报告保留、宽度记忆、取消、供应商失败均经真实 Electron 与本机模拟模型验证。日志保存在 `.tmp/code-review-20261102/`。
