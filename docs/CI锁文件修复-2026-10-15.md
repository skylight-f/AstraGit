# CI 锁文件修复

## 现象

main 上的 `25b9029`、`6c6969b`、`f1dd11d` 连续出现 CI 与 AstraGit Release 失败，后续版本未能自动发布。

## 根因与遗漏

最新提交 `f1dd11df6da6ca36c12a25176390a7741317fd59` 的 [CI 日志](https://github.com/skylight-f/AstraGit/actions/runs/38703481835) 明确显示：

```text
ERR_PNPM_OUTDATED_LOCKFILE
specifiers in the lockfile don't match specifiers in package.json:
* 1 dependencies were removed: @resvg/resvg-js@2.6.2
```

此前尝试图标渲染依赖后改用系统 AppKit 实现，没有把锁文件遗留的 importer、包元数据和平台快照同步清理。`25b9029` 引入该锁文件差异，后续两个提交沿用；CI 与 Release 都在 frozen-lockfile 安装阶段失败，尚未进入源码检查和 macOS 打包。

之前依赖现有 node_modules 的类型、lint、局部测试和 Renderer 构建不足以发现包清单与锁文件不一致，验收遗漏由本次修复补齐。

## 修复

- 通过 pnpm 10.31.0 离线重新生成锁文件，移除未使用的 resvg 及平台依赖，保留现有应用依赖版本。
- 新增 `pnpm check:lockfile`：执行 `pnpm install --lockfile-only --frozen-lockfile --offline`，无需重装正在开发的 node_modules。
- 完整 `pnpm verify:publish` 首先运行锁文件检查，再执行隔离、lint、类型、测试与构建。
- AGENTS.md 增加每次代码交付的锁文件检查，以及依赖 / 构建 / 更新 / 发布变更的干净安装和完整门禁要求。
- 保留云端 frozen-lockfile 校验。

## 验证进度

- 修复前，本地锁文件检查复现与 CI 相同的错误。
- 修复后，本地 `pnpm check:lockfile` 通过。
- 干净源码副本 `.tmp/ci-lockfile-repair-20261015` 的 `pnpm install --frozen-lockfile` 成功，安装 413 个包；未复用工作树的 node_modules。
- 同一干净目录完整 `pnpm verify:publish` 通过：锁文件、隔离、lint、全部类型检查、26/26 测试与所有包构建成功。
- 同一干净目录 `pnpm setup:desktop` 与 `pnpm build:app` 成功，生成正式身份 `AstraGit.app`；ASAR、独立生产依赖、打包 PNG 与源文件一致性、ad-hoc 签名校验均通过。未启动、安装或覆盖正式应用。
- 用户已确认「推送并恢复自动发布」，本次将推送 main 并验收对应 CI、双架构构建、公开 Release 及 Homebrew 同步，后续补充真实云端结果。
