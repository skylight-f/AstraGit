# 开发版钥匙串隔离修复

## 现象与根因

用户反复看到「AstraGit Development 想要使用钥匙串中的 AstraGit Safe Storage」。开发日志在多个 Main PID 中记录 `keychain_password_mac.mm` 的 `userCanceledErr (-128)`，热重启退出还曾等待原生钥匙串返回。

本地 Main 无条件调用 `app.setName('AstraGit')`，覆盖了开发外壳的独立名称。Electron 42.4.0 在 macOS 的 `PostCreateMainMessageLoop` 将 `app.getName() + ' Safe Storage'` 用作服务名；网络服务启动时为 Cookie 加密获取密钥。因此开发版与正式版虽然数据目录、Bundle ID 不同，仍访问同一个正式版条目。二者签名身份不同，开发版访问已有条目会触发授权；用户取消后下一次重启再次尝试。

该弹窗来自 Electron 的 Cookie 密钥读取；应用自身 AI Key 使用的 `securityCore.ts` 存储实现是另一条链路。

来源：[Electron 42.4.0 服务名设置](https://github.com/electron/electron/blob/v42.4.0/shell/browser/electron_browser_main_parts.cc#L486-L528)、[网络服务读取密钥](https://github.com/electron/electron/blob/v42.4.0/shell/browser/net/system_network_context_manager.cc#L253-L263)、[app.setName 文档](https://www.electronjs.org/docs/latest/api/app#appsetnamename)。

## 修复

- 新增 `applicationIdentity.ts`：在 ready 前为开发版设置 `AstraGit Development <工作区标识>`，正式版继续使用 `AstraGit`。
- 工作区标识由源码工作区路径的 SHA256 截取而来，同工作区稳定，不同检出目录隔离；端口与临时数据目录改变不导致身份漂移。
- Main 未收到开发数据覆盖参数时，也使用源码工作区 `.tmp/electron-development-data`，避免开发态回落到正式数据目录。
- 开发就绪日志和 `.tmp/dev-session.json` 记录内部名称，便于检查运行身份；没有写入令牌或密钥。
- 未改系统钥匙串条目、访问控制、正式数据、AI Key 存储或 Cookie 加密，未使用 mock-keychain。
