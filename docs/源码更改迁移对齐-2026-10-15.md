# 源码更改迁移对齐

## 原因与源码依据

用户指出先前源码更改界面与 Zeus 原实现相差过大，要求从实际最新代码核对，不能仅按截图另做样式。本次确认此前 AstraGit 的源码更改组件属于另行实现，遗漏了原有页签、仓库级联分支入口和三类分组，仓库双行卡片与持续展开的选项也改变了原结构。

已通过 `git ls-remote origin HEAD refs/heads/develop refs/heads/main` 核对：

| 来源 | 确认结果 |
| --- | --- |
| `/Users/skylight/MyCode/zeus` | 工作树干净，分支 develop，HEAD `cdce2b72eaf306c8b4450df99f02c86f0991f009`，与远端 develop 相同 |
| Zeus 远端 main | `56aa3fb148fec132218ccd0ff7986857dd907045`，2026-10-15 发布 v0.3.200；树中不存在 SourceGitChanges.tsx / sourceGitChanges.css |
| 定制源码更改组件 | develop 下 `apps/desktop/src/renderer/code/SourceGitChanges.tsx`；blob `535a7cf0f6ec36ef989826782c503f52f0f0c296` |
| 对应样式 | develop 下 `apps/desktop/src/renderer/code/sourceGitChanges.css`；blob `a9fe7a9bc00f943c328eba1d900d91c7e0b64a72` |

未把远端 main 更新日期等同于该定制功能的更新日期。本次对齐这套组件及其依赖的仓库操作入口，未宣称重新迁移整个 Zeus 最新主分支。

## 实现

1. `ProjectSourceChanges.tsx`：恢复「提交 / 贮藏」页签、冲突 / 更改 / 未版本控制分组、原搜索与视图切换、内嵌 AI 按钮和紧凑提交区。
2. `SourceFileTree.tsx`：按原 `SourceChangeTree` 的目录分组与排序规则实现树形 / 平铺；平铺显示 basename 与目录，状态用既有图标与 tooltip；仓库单行标题共用稳定颜色。筛选后的仓库 / 目录选择只作用于可见的本分组文件。
3. `SourceRepositoryControls.tsx`：重新接回已隔离的 BranchSwitcher、StashDialog、PushDialog、NewBranchDialog、CheckoutRevisionDialog、UpdateProjectDialog；分支与贮藏差异使用 AstraGit 自有 ProjectGitDiffWindow，替代 Zeus 原窗口桥接。
4. `sourceGitState.ts`：按项目保存 fileView，缺省 tree 与原代码一致；分组、仓库、目录折叠键分开，避免同仓库在不同状态组相互误折叠。
5. `sourceGit.css`：沿用实际原样式的字体、密度、留白和主题变量，补充独立应用侧栏与折叠选项的宿主布局，未链接 Zeus 的源码、包、构建产物或数据。
6. 原暂存 / 工作区范围、共用 / 逐仓库草稿、模型和父子模块选项收进「提交选项」；逐仓库草稿仍有显式仓库选择，暂存范围有可见标识。已有可用模型时，未启用的可选 Codex 提示放在选项中；没有可用模型时仍在提交区显示原因。
7. 原 Git 工作台、提交确认、真实 diff、索引保护、指纹验证、子先父后、失败推送重试等逻辑保留。新增操作与批次互斥，执行期间锁定跨项目 / 跨视图操作；已完成操作的刷新错误不会被当作 Git 操作失败。
