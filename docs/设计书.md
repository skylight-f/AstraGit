## 目标

AstraGit 是独立的本地 Git 桌面应用。它从 Zeus 的 Git 工作台提取部分实现，独立维护自己的包、应用身份和数据；不提供会话、任务工作树或数字团队工作流。

## 结构与数据流

```text
apps/desktop (Electron + React)
  └─ 带随机令牌的本机 HTTP 请求
      └─ packages/git-server (Fastify)
          ├─ 项目列表、操作历史、模型连接与 Codex 账户
          ├─ packages/git-core：仓库发现与 Git 操作
          ├─ packages/ai-runtime：HTTP 模型目录与 Codex App Server
          ├─ packages/storage：SQLite、命令回执与文件缓存
          └─ packages/shared：命令与错误等公共契约
```

所有工作区依赖都是本仓库的 `@astragit/*` 包。pnpm 工作区只包含 `apps/*` 和 `packages/*`；没有指向 Zeus 的源码路径、包链接或构建调用。静态模型目录固定自 pi-ai 0.87.1，普通模型请求由本应用直接执行，未引入 Pi 代理运行时。

Electron 主进程启动本机服务；preload 提供服务地址、令牌、目录选择与更新 IPC。Git 查询与写操作走 HTTP，更新下载、签名验证与安装交接由 Main 负责。项目 ID 对应本应用保存的绝对目录，仓库 ID 在该项目内解析，动作会验证仓库路径。

## 应用与数据隔离

Electron 在 readiness 前设置名称 `AstraGit`，并显式设置 `userData` 与 `sessionData`。macOS 默认使用 `~/Library/Application Support/AstraGit`，开发启动脚本使用 `.tmp/electron-development-data`；可通过 `ASTRAGIT_USER_DATA_DIR` 指定独立目录。

Codex CLI 启动前创建本应用的独立目录（新目录权限 0700），避免新安装应用因 `CODEX_HOME` 不存在而启动失败。目录存在与 CLI 可启动不代表账户已经登录。

| 数据 | 位置或规则 |
| --- | --- |
| 项目列表 | `{userData}/projects.json`；移除项目只移除记录 |
| 操作历史 | `{userData}/git-operation-history.json`；最近 2,000 条，50 条分页 |
| 模型与命令状态 | `{userData}/git-app.db`；SQLite WAL + FULL 同步提交 |
| 文件缓存 | `{userData}/artifacts/content-addressed` |
| 模型凭据 | 独立钥匙串 service `AstraGit`；回退 `{userData}/secrets.json` |
| Codex | `{userData}/codex`；所有进程显式覆盖继承的 `CODEX_HOME` |
| UI 状态与浏览器缓存 | 同一独立 Electron 数据目录；存储键使用 `astragit` 前缀 |

新数据库只初始化设置、审计、命令收发回执和文件缓存相关表，并写入独立 SQLite application_id。既有 AstraGit 数据保持可读，旧版本命令的 wire schema 与不可变回执哈希保持兼容；不删除已有表或自动迁移其他应用的数据。服务关闭时结束账户管理器与提交生成池中的 Codex 子进程。

## 功能现状

### 开发热更新（2026-10-14）

日常开发优先使用 `pnpm dev`。旧入口只在启动时执行一次全量构建，Main、preload 与后端包修改不会生效；现在使用独立开发监督进程：

- Renderer 直接加载 Vite，TSX/CSS 使用 Fast Refresh；shared 开发时解析到本仓库源码，避免读取旧 dist。
- App 的项目页签初始化每次挂载只执行一次，防止 Fast Refresh 重跑 effect 时把当前页面带回工作台。
- 监听 Main、preload、五个本地包的源码及 TypeScript/包配置。保存后合并事件，按依赖顺序编译，使用 pnpm 的 build 后同步机制更新注入式包。
- 全部编译成功才要求旧 Main 正常退出，等待服务与数据库关闭后启动新 Electron；编译失败保留旧应用，修复保存后重试。编译或退出期间继续保存会重新编译最新内容。
- 开发监督与 Main 通过只在非打包开发态启用的 IPC 交接。Main 的 SIGTERM/SIGINT 和父进程断开也走正常退出，不直接杀 Git 子进程。
- Vite 使用 middleware mode 和同一个本机 HTTP/WebSocket 服务，由监督进程统一处理信号；避免 Vite 自行 process.exit 提前中断清理。
- 默认独立数据 `.tmp/electron-development-data`。开发状态 `.tmp/dev-session.json` 只记录 PID、页面/API 地址、开发身份及目录，无认证令牌；退出后删除。
- 启动不构建 Renderer 的生产资源，也不生成正式应用或 DMG。开发 CSP 允许 React Refresh，生产 HTML 的 script-src 保持 self。

前端热更新通常保留 React 状态；后端重启从开发数据恢复已持久化状态，未保存的临时状态可能重置。正式构建仍用于明确的包、签名和安装验收。

真实开发应用已验证 TSX 修改及输入/导航保留、Main/preload 修改生效、shared/Git 服务重编译、编译失败保留旧应用及修复恢复、项目视图与草稿恢复、重复启动保护。10 月 14 日使用隔离的钥匙串替身验证 Ctrl+C 完整清理；10 月 15 日真实系统钥匙串发生原生退出等待，按用户要求跳过授权验收，不能把前者视为系统钥匙串成功。详见 [开发热更新验收记录](开发热更新验收-2026-10-14.md)。

### 项目双视图接入（2026-10-14，已接入并完成业务验收）

- 顶栏最左侧在项目页签之前显示当前视图名称，点击下拉选择 `仓库管理 / 项目提交`；按项目保存选择，批次忙碌期间禁用。原工作台保留，源码视图只聚合当前项目发现的 Git 仓库。
- 两种视图按特性命名：「仓库管理」（Repository management）侧重仓库分支、历史、暂存与同步；「项目提交」（Project commits）聚合当前项目内仓库的文件选择、AI 说明和批次提交。内部视图身份与存储键保持兼容。
- 两个视图复用仓库查询和刷新通知。切换视图保留各自的选择、查看位置与草稿；按项目保存视图偏好。
- 源码勾选记录提交范围。支持整文件工作区改动与所选文件的已暂存内容；AI 读取对应的真实 diff。
- 提交前绑定分支、HEAD 与内容指纹。通过临时索引冻结提交范围，成功后只同步所选索引条目，保留其他已暂存文件。
- 批次逐仓库记录结果；推送失败时保留已创建提交并只重试推送。子模块引用更新需在预览中明确选择。
- 验收采用一个项目内的多个临时 Git 仓库及本地裸远程；正式身份构建为 `AstraGit.app`。
