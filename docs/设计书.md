# AstraGit 设计与现状

## 目标

AstraGit 是独立的本地 Git 桌面应用。它从 Zeus 的 Git 工作台提取部分实现，独立维护自己的包、应用身份和数据；不提供会话、任务工作树或数字团队工作流。

## 结构与数据流

```text
apps/desktop (Electron + React)
  └─ 带随机令牌的本机 HTTP 请求
      └─ packages/git-server (Fastify)
          ├─ 项目列表、操作历史、模型连接与 Codex 账户
          ├─ packages/git-core：仓库发现与 Git 操作
          ├─ packages/ai-runtime：HTTP 模型目录与 Codex App Server
          ├─ packages/storage：SQLite、命令回执与文件缓存
          └─ packages/shared：命令与错误等公共契约
```

所有工作区依赖都是本仓库的 `@astragit/*` 包。pnpm 工作区只包含 `apps/*` 和 `packages/*`；没有指向 Zeus 的源码路径、包链接或构建调用。静态模型目录固定自 pi-ai 0.87.1，普通模型请求由本应用直接执行，未引入 Pi 代理运行时。

Electron 主进程启动本机服务；preload 提供服务地址、令牌、目录选择与更新 IPC。Git 查询与写操作走 HTTP，更新下载、签名验证与安装交接由 Main 负责。项目 ID 对应本应用保存的绝对目录，仓库 ID 在该项目内解析，动作会验证仓库路径。

## 应用与数据隔离

Electron 在 readiness 前设置名称 `AstraGit`，并显式设置 `userData` 与 `sessionData`。macOS 默认使用 `~/Library/Application Support/AstraGit`，开发启动脚本使用 `.tmp/electron-development-data`；可通过 `ASTRAGIT_USER_DATA_DIR` 指定独立目录。

Codex CLI 启动前创建本应用的独立目录（新目录权限 0700），避免新安装应用因 `CODEX_HOME` 不存在而启动失败。目录存在与 CLI 可启动不代表账户已经登录。

| 数据 | 位置或规则 |
| --- | --- |
| 项目列表 | `{userData}/projects.json`；移除项目只移除记录 |
| 操作历史 | `{userData}/git-operation-history.json`；最近 2,000 条，50 条分页 |
| 模型与命令状态 | `{userData}/git-app.db`；SQLite WAL + FULL 同步提交 |
| 文件缓存 | `{userData}/artifacts/content-addressed` |
| 模型凭据 | 独立钥匙串 service `AstraGit`；回退 `{userData}/secrets.json` |
| Codex | `{userData}/codex`；所有进程显式覆盖继承的 `CODEX_HOME` |
| UI 状态与浏览器缓存 | 同一独立 Electron 数据目录；存储键使用 `astragit` 前缀 |

新数据库只初始化设置、审计、命令收发回执和文件缓存相关表，并写入独立 SQLite application_id。既有 AstraGit 数据保持可读，旧版本命令的 wire schema 与不可变回执哈希保持兼容；不删除已有表或自动迁移其他应用的数据。服务关闭时结束账户管理器与提交生成池中的 Codex 子进程。

## 功能现状

### 开发热更新（2026-10-14）

日常开发优先使用 `pnpm dev`。旧入口只在启动时执行一次全量构建，Main、preload 与后端包修改不会生效；现在使用独立开发监督进程：

- Renderer 直接加载 Vite，TSX/CSS 使用 Fast Refresh；shared 开发时解析到本仓库源码，避免读取旧 dist。
- App 的项目页签初始化每次挂载只执行一次，防止 Fast Refresh 重跑 effect 时把当前页面带回工作台。
- 监听 Main、preload、五个本地包的源码及 TypeScript/包配置。保存后合并事件，按依赖顺序编译，使用 pnpm 的 build 后同步机制更新注入式包。
- 全部编译成功才要求旧 Main 正常退出，等待服务与数据库关闭后启动新 Electron；编译失败保留旧应用，修复保存后重试。编译或退出期间继续保存会重新编译最新内容。
- 开发监督与 Main 通过只在非打包开发态启用的 IPC 交接。Main 的 SIGTERM/SIGINT 和父进程断开也走正常退出，不直接杀 Git 子进程。
- Vite 使用 middleware mode 和同一个本机 HTTP/WebSocket 服务，由监督进程统一处理信号；避免 Vite 自行 process.exit 提前中断清理。
- 默认独立数据 `.tmp/electron-development-data`。开发状态 `.tmp/dev-session.json` 只记录 PID、页面/API 地址及目录，无认证令牌；退出后删除。
- 启动不构建 Renderer 的生产资源，也不生成正式应用或 DMG。开发 CSP 允许 React Refresh，生产 HTML 的 script-src 保持 self。

前端热更新通常保留 React 状态；后端重启从开发数据恢复已持久化状态，未保存的临时状态可能重置。正式构建仍用于明确的包、签名和安装验收。

真实开发应用已验证 TSX 修改及输入/导航保留、Main/preload 修改生效、shared/Git 服务重编译、编译失败保留旧应用及修复恢复、项目视图与草稿恢复、重复启动保护。10 月 14 日使用隔离的钥匙串替身验证 Ctrl+C 完整清理；10 月 15 日真实系统钥匙串发生原生退出等待，按用户要求跳过授权验收，不能把前者视为系统钥匙串成功。详见 [开发热更新验收记录](开发热更新验收-2026-10-14.md)。

### 拆分完善、设置与 Git 修复（2026-10-15，已发布 v0.1.5）

- **统一设置**：顶部入口改为「设置」，分为「通用 / AI 模型」。通用支持跟随系统、简体中文和 English，立即更新全部业务视图和文档语言，使用独立 localStorage 键保存。原模型配置嵌入统一设置；编辑连接名称、API 地址和目录路径时保留原密钥及模型选择。Codex 状态独立加载，避免阻塞普通模型配置。
- **Finder 工具路径**：已安装应用的提交日志显示 Husky 找不到 pnpm，退出码 127。Main 在服务启动前读取登录 shell 的绝对 PATH，传给 Git 子进程；不关闭 hooks，不复制 shell 中的其他环境变量。真实开发界面提交已执行 pnpm/Node hooks 并生成提交。
- **分支交互**：新增分支名在输入时验证空格、控制字符和非法引用语法，合法中文及 `#` 仍可用，Git 保留最终校验。切换分支可能覆盖本地修改时继续阻止操作，错误弹窗提供贮藏入口；确定未写入的校验失败记录为 `failed_before_write`。移除同一工作台错误的重复弹窗订阅。
- **数据与凭据**：项目、操作历史与回退密钥文件通过严格 JSON 读取及同目录原子写入持久化。损坏或不可读的数据明确报错并保留原文件；持久化成功后才更新内存，项目真实路径别名复用已有记录。既有 `secrets.json` 在重启后继续使用，避免钥匙串恢复时忽略回退密钥；钥匙串命令失败输出不回显密钥。
- **独立运行与网络**：同一数据目录使用单实例锁，串行创建窗口，防止重复启动服务。普通模型请求由桌面注入 Electron `net.fetch`，使用系统网络栈；独立 Node 服务保留默认 fetch。删除 Renderer 未使用的任务差异、会话命名和未实现的 WebSocket 入口，后端兼容命令契约保留。
- **开发身份**：macOS 开发启动缓存独立 `AstraGit Development.app`，使用本仓库图标和工作区独立 bundle ID；仍运行源码、Vite 与独立开发数据，不创建 ASAR/DMG，不覆盖正式安装。

`pnpm test` 22/22、typecheck、lint、isolation 均通过。真实开发应用验证中英文即时切换和重启保存、含 pnpm/Node 的提交 hooks、中文分支创建、未提交内容保护及贮藏入口、模型编辑后目录刷新与 AI 草稿生成。Git 业务验收写入均在临时仓库；之后按用户授权完成正式包验收、源码推送、v0.1.5 发布及已安装 Homebrew 0.1.4 → 0.1.5 升级。升级后项目、模型设置、既有操作历史保留，正式应用中文切换和再次检查更新通过。详见 [设置与 Git 修复验收](设置与Git修复验收-2026-10-15.md) 和 [正式发布与 Homebrew 升级验收](正式发布与Homebrew升级验收-2026-10-15.md)。

### 项目双视图接入（2026-10-14，已接入并完成业务验收）

- 顶栏最左侧在项目页签之前显示当前视图名称，点击下拉选择 `仓库管理 / 项目提交`；按项目保存选择，批次忙碌期间禁用。原工作台保留，源码视图只聚合当前项目发现的 Git 仓库。
- 两种视图按特性命名：「仓库管理」（Repository management）侧重仓库分支、历史、暂存与同步；「项目提交」（Project commits）聚合当前项目内仓库的文件选择、AI 说明和批次提交。内部视图身份与存储键保持兼容。
- 两个视图复用仓库查询和刷新通知。切换视图保留各自的选择、查看位置与草稿；按项目保存视图偏好。
- 源码勾选记录提交范围。支持整文件工作区改动与所选文件的已暂存内容；AI 读取对应的真实 diff。
- 提交前绑定分支、HEAD 与内容指纹。通过临时索引冻结提交范围，成功后只同步所选索引条目，保留其他已暂存文件。
- 批次逐仓库记录结果；推送失败时保留已创建提交并只重试推送。子模块引用更新需在预览中明确选择。
- 验收采用一个项目内的多个临时 Git 仓库及本地裸远程；正式身份构建为 `AstraGit.app`。

### AI 与多仓库提交补查（2026-10-15，后续本地修改，未发布）

- AI 输入明确携带工作区 / 暂存范围，所选暂存模式的提示词排除后续工作区修改；HTTP 和 Codex 使用同一个构造函数。
- 源码视图补齐生成文件摘要提醒和停止生成反馈；失败、取消均保留原草稿。批次后的刷新与重试错误显示在当前视图。
- 批次期间锁定项目和工作台 / 源码视图切换，防止同一用户从另一视图交错修改提交范围。
- 持久化批次的推送意图；已知 SHA 的中断推送可仅重试 push，结果不确定的 commit 继续要求核对，不自动重提。
- 24 项回归、类型、lint、隔离检查通过；真实热更新开发应用验证双仓库 AI 范围、逐仓库草稿、取消/失败恢复、选中暂存版本提交及重载后的推送重试，SHA 和提交数量不变。

本轮不提交、推送、正式构建或发布，不替换已安装 v0.1.5。完整证据和边界见 [AI 与多仓库提交检查](AI与多仓库提交检查-2026-10-15.md)。

| 领域 | 当前实现 |
| --- | --- |
| 项目 | 添加、打开、移除本地目录；恢复项目页签 |
| 工作台 | 状态、文件与区块级暂存/放弃、分支、历史、比较 diff、stash、提交、拉取与推送等 |
| 安全交互 | 高危 Git 操作确认；项目与仓库路径校验；同一仓库写操作互斥；中止请求 |
| 操作记录 | 动作、命令、输出、状态与耗时；重启后保留；未结束动作标记为需要核对 |
| AI 提交说明 | 模型连接、手动模型、目录刷新与启用、Codex 登录入口、diff 驱动的可编辑说明 |
| 界面 | 项目列表、通用语言与 AI 模型设置、仓库管理、项目提交、文件差异弹窗 |

AI 生成只产生草稿，不自动执行 commit。模型目录的新模型默认停用，用户显式启用。普通文本模型无需工具调用能力即可用于提交说明。Codex 使用临时独立会话，读取的 diff 由应用作为文本提供，临时工作目录在结束后删除。

工作台 API 包括 `/api/projects`、`/api/projects/:id/git/workbench` 的 history/commits/compare/actions/cancel 子路由，以及 `/api/projects/:id/git/operations`。模型与 Codex 使用 `/api/model-connections*`、`/api/codex/account*`；生成接口为 `/api/projects/:id/git/commit-message`。

### 加载状态下拉箭头修复（2026-10-15，本地未发布）

原生下拉控件的局部 background 简写会重置背景重复方式、尺寸和定位，而全局禁用规则只恢复背景图片，导致加载时箭头横向平铺。共用 select:disabled / aria-disabled 规则现在完整设置右侧居中、no-repeat、12px 尺寸和文本留白，覆盖直接禁用及 fieldset 继承禁用。开发应用验证真实本机推送与 AI 生成中的 5 个下拉框均无重复箭头，操作正常结束、草稿和选择保留；仅修改共享 CSS，未发布。见 [加载状态下拉箭头修复](加载状态下拉箭头修复-2026-10-15.md)。

## 验收范围

- `pnpm check:isolation` 检查源码、锁文件、工作区包及实际解析路径，禁止重新引入 Zeus 依赖。
- `pnpm typecheck`、`pnpm lint`、`pnpm build` 覆盖所有本地包。
- `pnpm test` 使用临时数据库与临时 Git 仓库，验证数据隔离、重启恢复、保存点/持久事务回滚、提交后通知、命令结果重放与 Codex 数据目录约束。
- 模拟模型端到端检查：暂存真实文件 → 刷新并启用模型 → 读取暂存 diff → NDJSON 返回草稿 → 提交 → 重启恢复项目、模型与操作历史。测试不访问真实模型，也不写入用户钥匙串。
- `pnpm build:app` 使用独立生产依赖树构建 `AstraGit.app`（`com.astragit.desktop`），打包为 ASAR 并校验本地 ad-hoc 签名。正式应用只加载包内页面，无需开发服务。
