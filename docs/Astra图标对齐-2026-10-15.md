# Astra 图标对齐

## 依据

用户说明 Astra 即本机 Zeus 定制版，要求参考其源码实现。核对路径 `/Users/skylight/MyCode/zeus`，当前为干净的 `develop@6ab59b15`，对应本机 `origin/develop`。

- `apps/desktop/assets/icon.png`：彩色几何叠片、黑色方块、白色 AT 和底部短横线。
- `codex/astra-at-branding@dec2c19e`：实际的 AT 品牌素材提交。
- `apps/desktop/src/main/main.ts`：`applicationIconPath` 与 `applyApplicationDockIcon`，使用透明 PNG 显式设置 Dock 图标。
- `apps/desktop/scripts/prepare-distribution-assets.mjs`：统一资源来源。
- `apps/desktop/scripts/render-svg.swift`：AppKit 原生 SVG 渲染方式。

没有修改 Zeus 工作树或读取其用户数据；参考实现独立维护于 AstraGit。

## 改动

1. 替换原蓝底 AG 图标，以 SVG 重建 Astra 的几何品牌风格，AG 区分独立 Git 应用。
2. 同一 SVG 用于页面 Logo 和 favicon；通过系统工具生成 1024px 透明 PNG 与 ICNS，保留不规则外轮廓。
3. `scripts/render-icon.swift` 使用显式像素画布，避免普通 NSImage lockFocus 在 Retina 屏幕上生成翻倍像素。
4. `scripts/generate-icons.mjs` 输出完整 16 / 32 / 128 / 256 / 512 及各自 @2x 的 10 档资源，全部完成后替换构建资源。新增 `pnpm icons:generate` 命令。
5. Main 在就绪后显式设置 Dock 图标；开发读取本项目 build/icon.png，正式包读取独立复制的 branding/icon.png。构建脚本核对复制的字节与源文件一致。
6. `pnpm dev` 增加图标资源监听；重新生成图标后自动编译并重启开发应用。Renderer 的 SVG、TSX 和 CSS 继续使用 Vite 热更新。

## 验证

- 1024 × 1024 PNG，带 Alpha，四角透明；有效轮廓在 `(70, 78)` 至 `(954, 950)`。
- 系统 iconutil 可完整解码 ICNS，10 档像素尺寸正确。
- 真实开发应用自动重启后正常加载，项目列表显示新的 AG 几何 Logo，原项目与提交草稿保留。
- 再次执行 `pnpm icons:generate`，监督进程识别 PNG / ICNS 变化并重新编译，Main 从 `78679` 恢复至 `92561`；界面复核仍为原项目、3 个文件 / 2 个仓库及原提交草稿。原生退出阶段等待系统钥匙串返回 `userCanceledErr (-128)` 后自行完成；准备恢复进程的保护检查发现 PID 已变化，未执行强制终止。
- Desktop 类型检查、lint、隔离检查和 Vite Renderer 资源构建通过；生产 HTML 与 JS 均引用打包后的本地图标资源。
- 系统 Dock 的电脑操作截图超时，不能将其计为 Dock 视觉验收；Main 已执行显式 PNG 加载并正常就绪。
