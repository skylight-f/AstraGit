### 主功能验收范围（2026-10-23 用户补充）

## 本机对照事实

在 `.tmp/sourcetree-alignment-20261022/blocked-tracked` 的独立临时仓库中：

1. 双击 `feature/target` 打开确认窗口，显示目标，并提供默认不勾选的 `Stash local changes`。
2. 普通切换被本地 `conflict.txt` 修改阻止，命令日志包含覆盖原因及该路径；分支仍为 `main`、本地内容保留。
3. 再次切换并勾选贮藏后，分支变为 `feature/target`、工作区干净，贮藏列表保留原 `main` 修改；未在目标分支自动恢复。

以上仅操作临时副本，没有在 SourceTree 中切换真实业务仓库。

## 本轮实现细节

- `git-core` 只从 Git 的覆盖保护段提取路径，并与操作前的 NUL 分隔状态路径核对；支持中文、空格、制表符和换行，不把无关修改列为覆盖文件。
- 文件数组与数量穿过服务、HTTP 客户端和错误原因模型；列表至多显示 200 项，完整数量单独保留。路径用于展示与定位，不作为新的写入授权。
- 通用错误窗口可展示核实状态、文件列表和多个业务处理入口，保留旧的单入口接口。结果不确定时不显示“未覆盖/未切换”的保护承诺，不自动重试写入。
- 本地分支切换确认可选择先贮藏，包含未跟踪文件；操作在仓库互斥区内执行，分支切换失败仍保留已创建的贮藏。贮藏未确认完成时不继续切换。成功后浮动提示可直接打开该条目。
- 已有冲突和未结束的整合在贮藏前拒绝；缺失目标先校验。post-checkout 钩子可能在分支已改变后失败，因此此类错误明确要求刷新核对，不能声称已回滚。
- 增加 `CHERRY_PICK_HEAD`、`REVERT_HEAD` 检测，继续/终止使用实际 Git 子命令；拒绝过期类型。终止整合先说明将放弃当前尚未提交的处理结果并确认。
