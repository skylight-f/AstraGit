# Git 操作提示布局修复

## 问题与原因

执行 Git 操作时，`ProjectGitWorkbench` 在正常文档流中插入整行 `.git-integration-actions`。顶部新增行挤压工作台，历史与差异区域随状态变化跳动，而且执行时通常只显示“中止操作”，缺少操作上下文。

## 修复

- 改为以工作台为定位容器的右下角悬浮提示，不参与面板高度计算。
- 显示实际执行操作的仓库名称、动作和加载指示；切换查看其他仓库时不借用其名称。
- 保留原有取消、继续和终止合并/变基行为及禁用条件。
- 使用主题色、宽度限制和可换行操作区；状态使用 `role="status"`，不抢占焦点。

## 验证

- `pnpm check:lockfile`、桌面包类型检查和修改组件 ESLint 通过。
- 在 `pnpm dev` 真实 Electron 应用中热更新验证，数据和仓库均位于 `.tmp`。
- 临时仓库仅连接本机裸仓库，通过临时 upload-pack 延迟保持抓取状态；截图确认工具栏、历史表格与差异面板在操作开始、中止前后位置一致。
- 点击浮层“中止操作”后后端返回 `ASTRAGIT_CANCELLED`，浮层消失，操作按钮恢复；移除延迟配置后再次抓取成功。
- 验收后已移除临时仓库的 upload-pack 配置。未修改正式用户仓库，未发布。

截图保存在 `.tmp/acceptance/git-operation-{before,floating,after-cancel}-20261016.png`。

## 经验总结

短时运行状态和中止入口应使用不参与内容布局的浮层；验证时同时检查出现、消失及取消后的面板位置，避免只验收静态截图。
