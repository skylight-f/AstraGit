# 文件状态标识对齐 Zeus

## 问题与原因

仓库管理的变更文件列表将子模块引用和普通修改文件都显示为黄色省略号。对照本机 Zeus 当前 `ProjectGitWorkbench.tsx` 的 `ChangeTreeEntry` 实现，缺失的是依据 `snapshot.submodules` 识别路径并使用 `Folder` 图标的分支；AstraGit 的项目提交列表已有此逻辑，普通文件状态组件也已与 Zeus 一致。

## 修复

在仓库管理中补齐子模块路径判断，子模块引用使用文件夹图标。普通文件保留新增的绿色加号、修改的黄色省略号、删除的红色减号、重命名的蓝色箭头、未跟踪的紫色问号，以及已有的冲突、复制和类型变化标识。暂存和未暂存列表继续按各自一侧的 Git 状态显示。

本次只迁移界面判断，运行时保持 AstraGit 独立，不引用 Zeus 文件或包。

## 验证

- `pnpm check:lockfile`、桌面包类型检查、修改组件 ESLint 和 `git diff --check` 通过。
- `pnpm dev` 真实 Electron 应用热更新验证；专用临时项目位于 `.tmp/file-markers-20261016/project`。
- 创建真实子模块并推进其提交，父仓库引用在未暂存、暂存、取消暂存后均为文件夹图标，差异仍显示真实 Subproject commit SHA。
- 同屏检查新增、修改、删除、重命名和未跟踪文件；`AM` 文件在已暂存侧显示新增、未暂存侧显示修改。
- 平铺和树状显示通过，验收后恢复原树状偏好及子模块未暂存状态。
- 未操作正式用户仓库，未正式构建、推送或发布。

界面证据：`.tmp/acceptance/file-markers-flat-20261016.png` 与 `.tmp/acceptance/file-markers-staged-20261016.png`。

## 经验总结

迁移时应核对实际调用处的分支，不能仅确认共用图标组件已存在。子模块引用是仓库元数据，应依据 Git 快照识别，不按路径外观猜测。
