# 钥匙串重复提示复查

## 原因

截图中的 `AstraGit Safe Storage` 属于 Electron/Chromium 的浏览器存储，不是保存 AI API Key 的 `AstraGit` service。此前仅修复了开发外壳与正式应用的名称隔离，不能覆盖所有触发源。

1. 当前运行时 Electron 42.4.0 存在上游问题：ESM 命名空间枚举会构造未使用的 `safeStorage`，并在 ready 时提前获取异步加密器，产生无业务需要的钥匙串访问。官方修复于 42.4.1 合入；本次升级到 Zeus 当前使用的同一维护分支版本 42.11.10。
2. 正式包指定独立验收数据目录时，内部名称仍为 `AstraGit`，因此不同签名的验收包会访问已安装应用的 Safe Storage 条目。
3. 已安装包为 ad-hoc 签名，没有稳定的 Developer ID 身份。即使消除前两项，真实 Cookie 加密访问仍可能在升级后被系统重新授权。
4. AI 密钥使用另一套原生钥匙串 API。模型配置、元数据与生成请求可能并发或重复读取同一账号；拒绝授权后也缺少进程内去重。

来源：[Electron 官方修复](https://github.com/electron/electron/pull/51924)、[Safe Storage 签名说明](https://www.electronjs.org/docs/latest/api/safe-storage)。Zeus 当前在 Main ready 前设置 `use-mock-keychain`，其浏览器存储策略与系统钥匙串加密不同，不能仅用运行时升级代替这一差异。

## 修复

- Electron 固定到 42.11.10，同步锁文件。
- Main 与原生更新窗口通过 `createRequire` 仅取得需要的 Electron API，避免 ESM 枚举初始化未使用模块。
- 正式包自定义数据目录使用稳定的 `AstraGit Profile <目录标识>` 名称；常规安装保留 `AstraGit` 和原有数据目录。开发名称规则保留。
- 用户明确选择与 Astra/Zeus 一致的策略：macOS 在 Main ready、Session 和窗口创建前追加 `use-mock-keychain`，开发包与正式包均生效。Chromium 浏览器态不再依赖系统钥匙串加密；其 Cookie 的本机加密保护相应降低。此开关不影响 git-server 使用 `security` 命令保存的 AI API Key。
- 原生 AI 密钥读取按账号共享进行中的 Promise，并在本次进程内缓存结果及授权失败；成功保存或删除后刷新缓存。文件回退仍实时读取，保持数据损坏检测。
- 不删除系统钥匙串条目、不修改其 ACL、不迁移正式用户数据。

## 验证

新增 macOS 策略和其他系统不变、并发读取、拒绝后不自动重试、保存后恢复、旧读取晚到不覆盖新密钥，以及打包验收身份跨版本稳定和隔离的测试。完整门禁与正式构建结果记录在 [本轮发布验收](发布验收-2026-11-03.md)。
