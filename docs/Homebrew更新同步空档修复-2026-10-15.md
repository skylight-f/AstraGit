# Homebrew 更新同步空档修复

## 现象与根因

已安装 AstraGit 0.1.5 检测到 0.1.6，点击下载后报「Homebrew Cask 尚未同步或与发布清单不一致」。失败后仍显示「正在同步 Homebrew」。

2026-10-15 15:27（北京时间）核对：

- [v0.1.6](https://github.com/skylight-f/AstraGit/releases/tag/v0.1.6) 于 15:19:50 公开，双架构 DMG、清单和 Cask 资产齐全。
- [官方 Tap](https://github.com/skylight-f/homebrew-tap/blob/main/Casks/astragit.rb) 和本机 Cask 都为 0.1.5，本机 Tap 干净且在 main，提交 `82ea356422b376e5c29b11cec9bd0766278355b7`。
- 最近一次 [Tap 同步任务](https://github.com/skylight-f/homebrew-tap/actions/runs/38697196341) 于 15:12:38 成功结束，早于 0.1.6 发布；未配置立即跨库同步时，依赖每 15 分钟的 GitHub 调度，实际运行可能延迟。

旧下载流程先同步 Tap 并断言 Cask 等于 Release，才开始下载。因此公开 Release 与 Tap 的同步空档会阻断下载。这次校验报错不代表 DMG 损坏或 Apple 公证失败。Renderer 失败时只设置错误，没有清除旧进度，并直接显示 Electron IPC 包装文字。

## 修复

1. Homebrew 与 DMG 下载都先写 `{userData}/updates/downloads/<version>/`。来源、架构、大小与 SHA-256 校验保持，失败只清理本次 partial。
2. 点击 Homebrew 升级时，先在当前应用内复核安装收据和 App 身份，再同步 Tap、核对 Cask。旧版本提示稍后重试，已下载文件保留；新版本或同版本摘要/地址异常分别提示，禁止安装。
3. Cask 匹配后，将已校验文件复制到 brew 缓存旁的唯一临时文件，复验后原子替换缓存。成功并确认后才启动安装辅助进程、退出应用。辅助进程仍复核收据、Cask 与缓存。
4. 更新动作开始和失败时清理旧进度，错误去掉内部 IPC 包装。下载后复查清单遇到网络错误时显示实际检查原因，不误报必须重新下载。

## 验证

- 更新专项回归 6/6：Tap 滞后不阻断下载；断网及 Cask 滞后/摘要不符不请求退出；同步完成后复用原下载；缓存原子复制；失败保留既有缓存；来源及两架构摘要校验。
- Desktop 类型检查、全仓 lint 通过。
- 真实 Electron `pnpm dev` 自动重编译并重启，界面下载失败后按钮恢复，提示不含 IPC 包装。开发包仍禁止下载正式更新，没有加入开发态安装旁路。
- 修复后的服务使用 `/Applications/AstraGit.app` 的只读 Homebrew 安装收据和真实公开发行，下载到项目 `.tmp/update-download-review-20261015`。119,048,193 字节；SHA-256 为 `99a3f07811ff92cb59416c500b1d6b22a7c57a34a5f7eb09e89432829b51adee`，与清单和 GitHub 资产一致；再次调用复用已下载文件。当本机 Cask 仍为 0.1.5 时，安装校验继续正确阻止。
- 第一次下载后的清单复查遇到短暂网络失败，下载文件保留；第二次复查成功。已修正该错误分支的提示。

## 边界

本轮修改未提交、推送、构建发行或替换正式应用；未执行 brew upgrade，也未修改本机或云端 Tap。正式 0.1.5 仍需等待 Tap 同步后重试下载；本地修复不会自动进入已安装应用。尚未以本轮代码验收实际应用替换和重启。
