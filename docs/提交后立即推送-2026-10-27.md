# 提交后立即推送

日期：2026-10-27。

## 行为

仓库管理的提交编辑区底部增加“立即推送变更到 remote/branch”复选框，默认不勾选。勾选后按钮显示“提交并推送”，点击或按 ⌘/Ctrl + Enter 均先提交当前仓库的已暂存内容，再推送。切换仓库、分支或目标后不会沿用旧目标的勾选状态。

已跟踪分支使用真实 upstream，支持远端与本地分支名不同、远程名包含斜杠。首次推送使用 origin，或唯一配置的远程，同名分支发布后建立跟踪。没有明确目标、没有远程或游离 HEAD 时禁用此选项，普通提交保持可用。

两个步骤共用界面操作锁。提交失败不开始推送并保留说明；提交完成立即清理草稿，后续推送失败明确显示本地已提交及提交短哈希，使用已有推送入口重试即可。提交与推送均核对当前分支和 HEAD；不强制推送、不自动重试提交、不暂存额外文件。

## 验证

使用 `pnpm dev` 的真实 Electron 应用，独立数据目录 `.tmp/commit-push-20261027/data`。所有操作仅在本轮创建的临时仓库与本机 bare remote 进行。

| 场景 | 界面与 Git 结果 |
| --- | --- |
| 已跟踪不同名目标 | 显示 origin/review/target；提交后仅该远端分支更新到新 HEAD |
| 首次推送 | 显示 origin/main；⌘ + Enter 提交并推送，建立 origin/main 跟踪 |
| 未勾选 | 只新增本地提交，远端保持空仓库 |
| 远端拒绝 | 显示“提交已完成，但推送未完成”及短哈希；本地新增一个提交，远端未变 |
| 提交钩子拒绝 | 说明保留、已暂存文件保留、本地 HEAD 与远端均未变 |
| 无远程 | 自动推送选项禁用，不误选其他仓库的远程 |

所有临时仓库的 `keep.txt` 未暂存修改字节保持不变。核对结果见 `.tmp/commit-push-20261027/ui-git-evidence.json`。

新增五项测试覆盖目标选择、真实提交及首次推送、钩子拒绝、推送失败后只重试推送、提交前及提交后分支变化拦截，全部通过。
