# Homebrew 发布权限导致持续升级失败

## 现场证据

- 正式运行进程的 `updates/app-ready.json` 记录版本 0.1.32、PID 89495；`/Applications/AstraGit.app` 的两个版本字段及 Homebrew 安装收据也均为 0.1.32。
- `updates/automatic-update-state.json` 在北京时间 2026-11-25 14:45 记录检测到 0.1.35，但升级后仍安装 0.1.32，错误代码为 `ASTRAGIT_UPDATE_HOMEBREW_NO_UPGRADE`。
- GitHub [v0.1.35](https://github.com/skylight-f/AstraGit/releases/tag/v0.1.35) 于北京时间 12:48:27 公开。远端 [Casks/astragit.rb](https://github.com/skylight-f/homebrew-tap/blob/main/Casks/astragit.rb) 仍为 0.1.32，文件对象 SHA 为 `33e7a83e15c6158867a63a16246cc93e13421e6e`；本机 Tap 的 HEAD 为 `6abd89705f49fe0aab1a7fa09fc963c95352c256`，版本同为 0.1.32。本机最近一次 fetch 为 14:44:48，已经读取到远端当前提交。
- 连续三次发行运行 `45340496854`、`45345624775`、`45548245847` 均在「同步 Homebrew Cask」步骤失败，构建和公开 Release 步骤成功。最近两次日志均明确记录：

  ```text
  Homebrew Git push 失败（exit=128）：remote: Permission to skylight-f/homebrew-tap.git denied to skylight-f.
  fatal: unable to access 'https://github.com/skylight-f/homebrew-tap/': The requested URL returned error: 403
  ```

  最新证据：[发行运行](https://github.com/skylight-f/AstraGit/actions/runs/45548245847)，发布 job `138986095689`。

## 根因与此前修复的缺口

发布工作流只检查 `HOMEBREW_TAP_TOKEN` 是否非空；Tap 可以被检出不代表凭据可以推送。新版先公开，随后 Tap 的 Git 推送遭到 403 拒绝，造成公开 Release 和 Homebrew 发行目录长期分离。客户端检测公开 Release 后执行正确的 brew upgrade 命令，但 Homebrew 的最新版仍是 0.1.32，因此命令可以成功结束而没有安装新版本。

之前处理过的元数据短暂同步空档、下载、系统代理和安装后版本复验，没有覆盖这次发布端的持续权限故障。此时反复检查、upgrade 或 reinstall 都无法获得未同步到 Cask 的新版；不能用更新文案或把 no-op 标为就绪来解决。

## 本地防复发修改

1. `scripts/sync-homebrew-tap.mjs` 提供 `--check-access`。检查固定 Tap 来源与干净工作区后，执行 `git push --dry-run origin HEAD:refs/heads/main`，校验当前凭据的 Git 推送入口权限，不移动远端引用。网络命令超时为 60 秒，权限拒绝保留实际诊断并指向所需凭据权限。
2. `.github/workflows/release.yml` 在 verify 阶段检出 Tap 并执行上述检查，失败时不进入发行候选与构建；在公开 Release 前再次检查，减少构建期间凭据失效造成的不完整发行。同步入口本身也先检查权限。
3. 在已有 `tests/release.test.mjs` 中增加内存回归：可读但不可推送的 403 拒绝、dry-run 不更新远端引用、错误来源和非干净检出提前停止。

dry-run 检查认证和引用协商，不能替代实际推送，也不能覆盖检查后发生的权限、分支规则或网络变化。发布完成仍必须核对实际 Tap 推送及对应云端工作流。

## 恢复当前故障需要的外部操作

1. 修正 [AstraGit Actions Secret](https://github.com/skylight-f/AstraGit/settings/secrets/actions) 中的 `HOMEBREW_TAP_TOKEN`：凭据必须覆盖 `skylight-f/homebrew-tap`，允许 Contents 读写并通过仓库访问策略；不能只给 AstraGit 仓库授权。现有工具不能读取或重新授权该 Secret。
2. 补同步已经公开的 **v0.1.35** Cask，并核对两架构摘要与公开 Release，确认远端 Cask 版本至少为 0.1.35。
3. 之后刷新本机 Homebrew，再从真实正式应用触发升级；核对安装收据、磁盘版本、重启后的进程版本与更新页面。

不建议直接重跑旧发行的失败 job：现有发布脚本要求远端 main 等于该发行提交，后续有新候选时旧 job 会被正确拦截。补同步应绑定实际已公开标签及其 sourceCommit，或在权限恢复后通过新的完整发行完成同步。
