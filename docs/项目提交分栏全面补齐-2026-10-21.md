# 项目提交分栏全面补齐

日期：2026-10-21；本地开发热更新验证，未正式打包或发布。

## 现象与根因

项目提交此前只增加文件列表与提交说明的上下分隔条，主侧栏仍固定 410px、批次结果高度限制为 30%，差异旧/新列与冲突各编辑区也没有调整入口。差异视图每 5 秒刷新仓库快照时先清空差异数据，再显示读取占位，使组件卸载；布局模式与滚动位置因此重置，正在使用的分隔条也会消失。共享分隔条的边界变化还会重新读取旧存储值，无法保留本次调整偏好。

## 修复范围

| 分栏 | 偏好键尾缀 | 默认比例 |
| --- | --- | --- |
| 主文件列表 / 详情 | `source-sidebar` | 32% |
| 文件列表 / 提交说明 | `source-files` | 82%，沿用既有实现 |
| 差异 / 最近批次结果 | `source-results` | 78% |
| 差异旧 / 新列 | `diff-columns` | 50% |
| 冲突当前 / 传入 | `conflict-current` | 50% |
| 版本对照 / 合并结果 | `conflict-versions` | 42% |
| 多文件差异文件列表 / 详情 | `diff-window-files` | 24% |

偏好使用 `astragit.git.panes.v1.<尾缀>`，统一支持指针、方向键、双击及 Home/Enter 复位。偏好恢复与动态范围夹取分离，小窗口只临时约束显示值，放大恢复原偏好。差异表头和所有 hunk 共用同一个列比例，不分别存储；观察有效宽度，正常每侧至少 120px，空间不足时均分。多文件差异窗口正常保留文件列表至少 160px、差异至少 280px，总宽不足 446px 时均分。提交区按实际控件尺寸预留按钮空间，选项向上浮层不被裁切。

同文件刷新保留旧差异至新结果成功，目标切换继续显示读取状态，过期请求由 AbortController 忽略；失败显示本次错误，不能把旧数据当作新目标成功。分隔条拖动期间跳过定时刷新。冲突调整仅改变布局，不改写 Monaco 文本、索引或工作区。
