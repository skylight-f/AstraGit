# 差异颜色与对齐修复

## 问题与原因

对照本机 Zeus 当前 `ProjectGitDiffViewer.tsx`、`code/CodeDiffView.tsx` 和 `codeDiffView.css`，Zeus 使用结构化差异视图，具有行背景与替换对齐。AstraGit 拆分后的实现将左右内容用固定 72 字符和竖线拼成一个 `pre`，没有逐行元素及状态，导致红绿颜色和行内高亮缺失，替换行上下错开，长行也会推挤右侧。

## 修复

- 将真实 `GitDiffHunk.lines` 渲染为独立行，删除为红色、新增为绿色，保留加减符号。
- 按 Zeus 连续变更块配对方式对齐左右行；不同数量的增删行使用无行号的空位，真实空行仍保留行号。
- 在配对替换行中按共同前后文高亮变化片段；按 Unicode 码点处理，不拆开 emoji，不改写空白和原文。
- 左右面板独立水平滚动、同步垂直位置；统一视图使用原始补丁顺序，显示原始/新文件两列行号。
- 区块范围按原始和新文件分别显示，零行范围显示“空”，修复新增文件原范围 `0–-1`。
- 使用共用差异组件覆盖各入口，不修改原始 hunk 或区块暂存/放弃 API，无新依赖及 Zeus 运行依赖。

## 验证

- 两项新增回归测试通过：不等长替换块的原文/行号/空位/长行/元数据完整性，以及 Unicode、空白和行内变化范围。
- `pnpm check:lockfile`、桌面类型检查、修改文件 ESLint、渲染生产构建通过。
- 使用 `pnpm dev` 真实 Electron 热更新，专用临时项目包含模板长行、增删、数字替换和中文 emoji 替换。
- 左右对比和统一视图中红绿行背景与行内加深高亮可见；替换行、上下文和真实行号正确。
- 真实区块暂存及取消暂存通过；验收后原有三条已暂存文件保持不变，测试文件恢复未暂存状态。
- 未正式构建应用，未推送或发布。

## 经验总结

差异属于结构化数据，不能用纯文本拼接代替界面结构。显示层的配对和着色必须保留原始补丁、行号与内容，确保视觉修复不影响 Git 写入操作。
