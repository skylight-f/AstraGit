# AstraGit 开发热更新检查与验收

日期：2026-10-14；分支：`main`；源码版本：0.1.4 加本次本地修改。

## 本次范围

按用户要求暂停发布与升级验收，改为检查开发链路并优先使用 `pnpm dev` 验证。开始时核对本次升级验收的进程，均已结束；本轮没有提交、推送或触发发行，也没有生成正式 App / DMG。

实际环境：Node 24.20.0、pnpm 10.31.0、Electron 42.4.0、Vite 8.3.0，macOS arm64。Renderer 加载 `http://127.0.0.1:5179/`，Git API 使用随机本机端口。

## 检查发现与修复

| 问题 | 修复 |
| --- | --- |
| 旧入口只启动时构建一次，Main/preload/后端源码修改不生效 | 保存后按依赖顺序编译，成功才正常退出旧 Main 并启动新进程 |
| 注入式工作区可能读取未同步的 dist | 使用 pnpm build 同步机制；Renderer 的 shared 直接解析本地源码 |
| Fast Refresh 重跑初始化 effect，导航被带回工作台 | 项目恢复每次挂载只执行一次，保留当前开发页面 |
| Vite 的 SIGTERM 处理提前退出监督进程，留下状态文件 | middleware mode + 自有 HTTP/WebSocket，监督进程统一等待并清理 |
| HTML 自带开发用宽松 script-src，开发插件无法区分生产 | HTML 保持 self；只有开发 transform 加入 React Refresh 需要的配置 |

## 开发约定与边界

- 日常入口为 `pnpm dev`，规则写入根目录 `AGENTS.md` 与 README。
- 默认开发数据是 `.tmp/electron-development-data`；本次显式指定验收目录，未使用正式用户数据。
- Renderer 的兼容组件修改通常保留状态；改变 hook 结构或触发整页刷新可能重置临时状态。Main/preload/后端修改通过正常重启生效，已保存草稿与设置从开发数据恢复。
- 退出会等待当前请求完成，实际长时间 Git/AI 请求可能延迟退出；不会为缩短等待强杀 Git。
- 本次关闭 Codex，并使用验收目录中的 security 命令替身避免系统钥匙串提示。真实供应商、Codex 登录、系统钥匙串、签名包安装与更新不属于本次热更新验证。
- Renderer 生产资源构建仅用于 CSP 分离检查；已有资源体积警告保留，未进行打包或正式发行。

Vite 集成依据：[JavaScript API](https://vite.dev/guide/api-javascript.html)、[middleware/WebSocket 配置](https://vite.dev/config/server-options.html)。
