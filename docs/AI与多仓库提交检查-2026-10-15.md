# AI 自动填写与项目内多仓库提交检查

## 范围

在已发布 v0.1.5 源码基线上继续检查。用户要求发现问题直接补齐，优先真实 `pnpm dev` 热更新验证，暂不发布。本轮不构建发行包、不提交或推送源码、不替换已安装的正式应用。

业务链路：当前项目内勾选文件 → 选择工作区或暂存范围 → 本机 API 读取真实 diff → 生成可编辑草稿 → 逐仓库预览和提交 → 记录 SHA → 失败或中断后仅重试推送。

## 发现并补齐

| 问题 | 证据 | 修复 |
| --- | --- | --- |
| AI 的范围说明与暂存模式不符 | 新回归复现：传入 staged，实际 diff 为暂存版本，提示词却称完整工作区改动 | 将 selectionMode 传入共享提示词构造；HTTP 与 Codex 共用，明确排除工作区后续修改 |
| 中断后已完成的提交不能恢复推送 | 新回归复现：pushing 恢复为 unknown；提交后尚未进入推送的 committed 丢失推送意图 | 持久化 pushRequested；有 SHA 的中断推送恢复为 push_blocked，保留仅推送入口；未确定提交结果的 committing 仍要求人工核对 |
| 源码批次中能切回工作台操作同一项目 | App 只禁用项目页签，未禁用两个视图切换按钮 | 批次执行期间禁用视图切换，处理函数同时防守；保留停止批次入口 |
| AI 部分内容摘要、取消缺少说明 | 源码视图忽略返回的 truncated，取消只恢复草稿 | 共用与逐仓库模式都汇总摘要提醒；停止时显示原说明已保留；状态提示增加 role=status |
| 批次后刷新失败可能无可见提示 | 确认框已关闭后仍写入其错误状态；推送重试缺少 catch | 已开始的批次错误显示在主视图，预检错误留在确认框；重试异常可见并始终解除忙碌状态 |

## 自动验证

- `pnpm test`：24/24 通过，包括新增 AI 多仓库范围和中断恢复回归。
- `pnpm typecheck`、`pnpm lint`、`pnpm check:isolation`：通过。
- AI 回归通过真实 Renderer 客户端和本机 API，验证同一项目两个仓库的所选 staged / worktree 差异；未勾选文件不进入提示，生成期间所选内容变化则拒绝结果，AI 不改变 HEAD 或索引。
- 恢复回归区分 pushing、带推送意图的 committed、只提交的 committed、结果未确定的 committing；既有子模块回归验证子先父后、未勾选索引保护及只重试 push。

## 真实开发应用与热更新

独立开发数据：`.tmp/ai-multi-review-20261015/data`。一个项目含 `core`、`web` 两个临时 Git 仓库；本机模拟模型，虚构凭据，关闭 Codex，不读取正式用户数据。

1. 真实 Electron 页面 `127.0.0.1:5179`，Main PID 90717。两个仓库各有部分暂存的 selected.txt 和未勾选的暂存文件。
2. 只勾选两仓库的 selected.txt，选择「仅已暂存内容」生成草稿。模拟服务记录范围为两个 selected.txt；提示词为所选暂存内容，没有 later working tree 或未勾选 keep staged。
3. 输入人工草稿，模拟慢响应，点击停止：人工文本保留，提示「已停止生成，已保留原提交说明」。再模拟 HTTP 503，错误可见，原草稿仍保留。
4. 勾选暂存锁文件后生成，界面显示「部分大文件或生成文件仅提供摘要，请核对完整性」。取消该文件勾选后继续逐仓库模式。
5. 「每个仓库单独填写」分别生成 feat(core)、feat(web) 草稿；确认页列出每仓库独立说明和唯一勾选文件。
6. 确认提交时，项目入口和两个视图切换按钮均禁用。两个真实提交为 core `03d7a503`、web `3519d54b`。独立读取 Git 对象确认仅提交暂存版本，工作区后续修改保留，unchecked.txt 和未勾选锁文件仍在原索引中。
7. 在 core 的本地裸远程使用延迟并拒绝的接收 hook，提交 resume.txt 后进入推送中，提交 SHA `da6281e95ba2a48a146f48fcde95bc9182d1517a`。实际重载 Renderer 后，批次恢复出重试推送入口；允许本机远程接收后重试成功。HEAD 和提交数量（3）不变，远程 main 指向同一 SHA，未重复提交。
8. 前端保存后 Fast Refresh，已选两个文件和草稿保留；本轮全程使用开发应用，未进行正式构建。

## 边界

- 真实 HTTP 供应商和真实 Codex 账号没有在本轮重新验收；模型响应来自本机模拟服务，Codex 仅继续通过独立 CLI 握手回归。提示词修复由两种生成路径共用。
- 远程推送使用本地裸仓库。无外部远程写入，无正式用户项目提交或分支操作。
- Renderer 重载时旧请求报告 Failed to fetch，界面可重试并成功；纯持久化的 pushing / committed 恢复分支由新增回归覆盖。未把页面重载等同于操作系统崩溃验收。
- 已提交但未记录到 SHA 的结果仍保持 unknown，不自动重复提交。旧记录没有 pushRequested 时不推断推送意图。
- 当前修改只在本地，已安装 v0.1.5 不包含本轮修复。
