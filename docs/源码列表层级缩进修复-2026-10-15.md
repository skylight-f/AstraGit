# 源码列表层级缩进修复

## 问题

项目提交视图中，文件属于仓库的子项，但平铺文件的复选框比仓库复选框更靠左；更改与未版本控制的文件分组均受影响。

## 根因

`SourceFileTree.tsx` 的仓库和目录行包含折叠箭头，叶子文件没有箭头列。`sourceGit.css` 又在平铺模式将文件行 `padding-left` 清零。父子行结构与留白计算不一致，导致子项视觉上向左越过父级；树形文件与同层目录也没有严格对齐。

## 修复

只修改 `apps/desktop/src/renderer/git/sourceGit.css`：

- 用 `--source-git-indent: 16px` 统一仓库及每层文件树的缩进。
- 文件行通过空的 `::before` 保留 12px 箭头列，统一行内 5px 间距和两侧 4px 留白。
- 去除平铺文件清零缩进的覆盖；文件按钮不再额外增加左侧 2px 留白，使同层目录与文件的复选框、状态图标对齐。
- 没有修改选择、展开、AI 或 Git 操作逻辑。

## 验证

真实 `pnpm dev` 的 Vite CSS 热更新：

1. 平铺：core / web 仓库下的文件均在父仓库右侧；更改和未版本控制分组均正常。
2. 树形：web → pages → build-platform → index.vue 逐级向右；同层目录和根文件复选框对齐，utils/category-tree.ts 也保持父子层级。
3. 展开 / 折叠与视图切换正常，验收后恢复原平铺显示及目录折叠偏好。
4. 原有 3 个文件 / 2 个仓库的勾选和 `feat: 更新选中内容` 草稿保留。
5. `git diff --check` 通过。

本轮为样式修复，未执行正式构建、提交、推送或发布。
